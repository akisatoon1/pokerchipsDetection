# push の前の確認

まだ push していないコミットに, GitHub に上げてはいけないものが入っていないかを調べて, 人に報告する.
push は人が行うので, このスキルは調べて報告するところまでにする.

## 見る範囲

最新の状態ではなく, **まだ push していない全コミット** を見る.
後のコミットで消したファイルも, push すれば履歴に残り, 誰でも取り出せるため.

## 手順

### 1. リモートの状態を新しくする

```sh
git fetch origin
```

リモートの状態が古いと, push 済みのコミットまで調べたり, 見るべきコミットを見落としたりするため.
ネットにつながらず失敗したら, そのことを報告に書いて続ける.

### 2. 機械的な検査を流す

リポジトリのルートで流す.

```sh
python3 -I .claude/skills/pre-push-check/scan.py
```

範囲は, 追跡しているリモートのブランチ (なければ `origin/<今のブランチ>`) から HEAD まで.
別の範囲を見るときは `scan.py origin/main..HEAD` のように渡す.

調べること:

| 検査 | 内容 |
|---|---|
| 置いてはいけないファイル | `.env`, `.dev.vars`, 鍵, `local.properties`, `.claude/settings.local.json`, `node_modules/` や `build/` などのビルド結果, `*.onnx` などのモデル |
| 秘密情報らしい文字列 | 追加した行とコミットメッセージにある API キー, トークン, 秘密鍵, 本番の D1 の id, 手元の絶対パス, メールアドレス |
| 大きいファイル | 5 MB を超えるファイル. 50 MB を超えるものは NG (GitHub は 100 MB で拒否する) |
| 画像の位置情報 | 新しく上がる画像の EXIF に GPS の情報があるか |
| 無視するはずのファイル | `.gitignore` に当たるのに追跡しているファイル |

出力の `[NG]` は上げてはいけないもの, `[要確認]` は人が判断するもの.
見つけた値は, 漏れないように先頭だけを残して伏せてある.

### 3. スクリプトでは分からないものを見る

スクリプトは決まった形しか見つけられないので, 次も自分で見る.

```sh
git log --oneline <範囲>
git diff --stat <範囲の最初>..HEAD
git log --format= --name-only --diff-filter=A <範囲> | sort -u
```

- **足したファイルの一覧**: 用途の分からないファイル, 手元でだけ使うメモや一時ファイル, 試しに出した画像やログがないか.
- **`[要確認]` の中身**: 当たった行の前後を `git show <コミット> -- <パス>` で見て, 本物の秘密か, テストの値や例かを判断する.
  例: テストで作るトークン, `example.com` のアドレス, `wrangler.toml` の `00000000-...` の仮の id は問題ない.
- **写真**: 新しく足した写真 (`testimages/` など) に, 人の顔や名前, 住所などの個人が分かるものが写っていないか.
  枚数が多ければ, 一覧を人に示して確かめてもらう.
- **本番の値**: 本番の URL やデプロイ先の id が, 仮の値 (`https://example.invalid` など) のままか.
  このリポジトリでは, 本物の値はデプロイするときに入れる決まり (`web/wrangler.toml`, `android/app/build.gradle.kts`).

### 4. 報告する

日本語で次の順に書く.

1. **結論**: push してよいか. 「NG なし, 要確認なし」なら push してよいと書く.
2. **見た範囲**: 範囲とコミットの数. fetch に失敗したならそのこと.
3. **NG**: 何が, どのコミットのどのファイルにあるか. なぜいけないか.
4. **要確認**: 判断の結果 (問題ない / 人に判断してほしい) と理由.
5. **直し方の案** (NG があるとき).

秘密の値そのものは報告に書かない. スクリプトが伏せた形のまま示す.

## 見つかったときにしないこと

- **push しない.** push は人が行う.
- **人に指示されるまで履歴を書き換えない** (`git rebase`, `git commit --amend`, `git reset`, `git filter-repo` など).
  まだ push していなくても, 消したいファイルを含むコミットを直すには履歴を書き換える必要がある.
  どのコミットをどう直すかの案を示し, 人の指示を待つ.
- 後のコミットで消すだけでは直らないことを伝える. 履歴に残るため.
- 本物の秘密情報 (API キー, トークン) が入っていたなら, 履歴から消すのに加えて, その値を無効にして作り直すよう勧める.
  手元の別のところに漏れているかもしれないため.
- 足りない `.gitignore` の規則があれば, 足す案も示す.
