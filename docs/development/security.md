# セキュリティと個人情報

すべての作業 (C++, Web, Android, 文書, スクリプト) で守る, セキュリティと個人情報の規則をまとめる.
人が行うときも, AI が行うときも, この文書に従う.
Web アプリに固有の規則 (トークン, 権限の確認, XSS など) は [web/security.md](web/security.md) にある.

リポジトリは GitHub で公開している. push したものは誰でも読め, 後のコミットで消しても履歴から取り出せる.
複製やキャッシュにも残りうるので, 上げたものは取り消せないと考える. 規則はこの前提から決めている.

## リポジトリに上げないもの

- **秘密情報**: API キー, トークン (Cloudflare, GitHub など), パスワード, 秘密鍵, `.env`, `.dev.vars`.
  コードや設定のファイルに書かず, 実行するときに環境変数や CI の Secrets から渡す.
- **手元だけの設定**: `android/local.properties`, `.claude/settings.local.json` など. 手元のパスや好みが入っているため.
- **個人情報**:
  - 手元の絶対パス (`/home/<ユーザー名>/...`) やユーザー名. 文書やコードには, リポジトリからの相対パスか `~/...` で書く.
  - メールアドレス, 本名, 住所. コミットの作者のメールアドレスは除く (push 済みのコミットと同じものを使う).
  - 写真の EXIF にある位置情報 (GPS). テスト画像などの写真を足す前に確かめ, あれば消す. 撮った場所が分かるため.
  - 写真に写った, 個人が分かるもの (人の顔, 名前, 住所, 画面の中身など).

## push の前に確かめる

push は人が行う. push の前に, スキル `pre-push-check` (`.claude/skills/pre-push-check/`) で,
まだ push していない全コミットに上の「上げないもの」が入っていないかを調べる.
最新の状態だけでなく全コミットを見るのは, 途中のコミットで足して消したものも履歴に残るため.

## 上げてしまったとき

- すぐに作業を止めて人に報告すること. 対処をするために作業などせずに, まず人に状況報告をして対処法を提案せよ.
- 後のコミットで消すだけでは直らない. 履歴に残るため.
- 秘密情報なら, すぐにその値を無効にし, 作り直す. 履歴から消すより先に行う. 公開した時点で誰かが取った前提で動くため.
- 履歴の書き換え (`git rebase`, `git filter-repo` など) は, 人に指示されたときだけ行う. どのコミットをどう直すかの案を示して, 指示を待つ.

## 外から取ってくるもの

依存ライブラリ, ツール, ダウンロードするファイル, CI で使う action のこと.

- **版を固定する.** `package-lock.json`, スクリプトの中の版 (Emscripten, OpenCV など), CI の action のコミットの SHA.
  勝手に新しい版に変わり, 乗っ取られた版を取り込むのを防ぐため.
- **取ったファイルを確かめる.** 配布元が sha256 などを出していれば, 一致を確かめてから使う (Node の tarball, `gradle-wrapper.jar` など).
- **公式の配布元から取る.** 出どころの分からない複製から取らない.
- **既知の脆弱性を検査する.** 検査の道具がある分野では, コミット前の検査に入れる (Web は `npm run check` の `npm audit`).

## 秘密情報を使う仕組み (CI, デプロイ)

- トークンの権限は, 使う操作と対象 (アカウント, リポジトリ) だけに絞る. 漏れたときの被害を小さくするため.
- トークンをログ, エラーの表示, コミットメッセージに出さない.
