# コーディング規約

C++ のコード (`core/`, `cli/`, `android/app/src/main/cpp/`) の書き方をまとめる.
人が書くときも, AI に書かせるときも, この文書に従う.

## 整形と検査

- 整形は clang-format (`.clang-format`) に任せる. 手で揃えない.
- コードを変えたら `make format` で整形し, `make format-check` と `make tidy` が通ることを確かめる.

## Doxygen コメント

### 何に付けるか

関数の外側 (ファイル / namespace スコープ) で宣言・定義しているものすべてに付ける.

- 関数 (メンバ関数を含む)
- 型 (struct / class / enum) と, そのメンバ・列挙子
- 変数・定数

付けなくてよいもの:

- 関数の中のローカル変数. 処理の説明は普通の `//` コメントで書く.
- テスト (`tests/*.cpp`).
- 名前を見れば分かる列挙子 (`kRed` など).

### どこに書くか

| 対象 | 書く場所 |
|---|---|
| 公開しているもの (ヘッダで宣言している関数・型) | ヘッダの宣言 |
| 公開していないもの (匿名 namespace の関数・型・定数, private メンバ関数) | `.cpp` の定義 |
| ヘッダのない関数 (JNI の関数, `main`) | 定義 |
| private メンバ変数 | ヘッダの宣言 (宣言がヘッダにしかないため) |

同じ説明をヘッダと `.cpp` の両方に書かない.

### 書式

説明が **1 行で済むなら `//!`**, **2 行以上なら `/** */`** にする. `///` は使わない.

#### 1 行: `//!`

`@brief` は付けない. メンバ・列挙子・定数で使うことが多い.

```cpp
//! end2end 形式の出力 [1, N, 6] の最後の次元の大きさ.
const int kEnd2EndFields = 6;
```

```cpp
struct StackResult {
  //! スタックの領域. 元画像の座標系.
  cv::Rect box;

  //! 検出スコア. 手動選択なら 1.
  float score = 1.0F;
};
```

行末に書く形 (`int x;  //!< 説明`) は使わない. 説明は対象の前の行に書く.

#### 2 行以上: `/** */`

- 1 行目を `@brief` にする.
- 詳しい説明 (なぜそうするか) があれば, ` *` だけの空行を挟んで続ける.
- 関数は全部の引数に `@param`, 戻り値があれば `@return` を書く. 例外を投げうるなら `@throws` も書く.

```cpp
/**
 * @brief 画像をアスペクト比を保ったまま正方形に収め, 余白を埋める.
 *
 * ultralytics の LetterBox(auto=False, center=True) と同じ計算をする.
 * 前処理が違うと検出結果がずれるため, 丸め方まで合わせている.
 * @param bgr 元画像 (BGR).
 * @param size 正方形の一辺 (px).
 * @return 余白を埋めた画像と, 座標を戻すための縮小率と余白の量.
 */
Letterbox letterbox(const cv::Mat &bgr, int size);
```

```cpp
/**
 * @brief 灰とみなす V の上限.
 *
 * V が kGrayMaxV 以上の低彩度画素は白っぽいので無視する.
 */
const int kGrayMaxV = 200;
```

関数のコメントには `@param` などが入るので, 普通は `/** */` になる.

### 空行

Doxygen コメントの前には空行を入れる.
ただし `{` やアクセス指定子 (`public:` など) のすぐ後は空行を入れない.

```cpp
enum class ChipColor {
  kRed,
  kBlue,

  //! どのクラスにも属さない. 最後に置き, クラス数として使う.
  kUnknown
};
```

### 内容

- 何をするか (`@brief`) に加えて, **なぜそうするか** を書く. 理由は後から読む人がいちばん困る情報なので, 消さない.
- 単位 (px, 要素数) や座標系 (元画像 / letterbox 後) など, 型だけでは分からないことを書く.
- 失敗したときに何を返すか (`nullopt`, 空の矩形など) を `@return` に書く.
