## 計画

### 決めたこと

- 色は今の 7 色 (赤, 青, 黄, 黒, 灰, 紫, 緑) のまま変えない. 変えるのは, 色ごとの点数を持つ場所だけにする.
- 点数は, リーダーがマッチを作るときに入れ, そのマッチに保存する. マッチの全員が同じ点数で換算する.
  - 1 色につき 1〜1,000,000,000 の整数. 空欄は「使わない色」. 少なくとも 1 色は入れる.
- リーダーはいつでも点数を変えられる. 入力中のラウンドがあってもよく, 確定したラウンドのあとでもよい. 変えられるのはリーダーだけ.
  - 変えても, もう保存した持ち点は変わらない. バックエンドが保存するのは持ち点だけで, 点数は換算に使うだけのため. 変更の画面にもそう書く.
  - 「チップから入力」を開いたときに, マッチを読み直して最新の点数を使う. 他の人の変更をポーリングしないので, 開いたままの画面が古い点数で換算しないようにするため.
- 持ち点への換算は, 今までどおり画面で行う. バックエンドは点数を保存して返すだけで, 受け取るのは今までどおり持ち点だけ.
- ブラウザに保存する設定 (`/chips` と localStorage) は消す. `/count` は枚数と色だけを出し, 持ち点は出さない.
- この変更より前に作ったマッチには点数がない. そのマッチでは「チップから入力」を押せなくし, 「リーダーが点数を決めると使えます」と出す. リーダーは変更の画面から決められる.
- 作業はブランチ `feat/match-chip-values` で行う. 人の指示によるもので, process.md の「main に直接コミットする」はこの作業にだけ当てはめない. merge と push は人が行う.

### 機能と順番

#### 0. 仕様を直す

- `docs/web/app.md`: データ (Match に色ごとの点数), 操作の表 (マッチを作る, 色ごとの点数を変える), 「色と点数の設定」「チップから入力する」「数えるだけの画面」「トップページ」, API の表
- `docs/development/web/layers.md`: 画面が規則を呼ぶ説明の言い回し
- `docs/architecture.md`: 関係する記述があれば直す

#### 1. マッチを作るときに色ごとの点数を決める

- DB: `web/migrations/0004_create_match_chip_values.sql` を足す. 表 `match_chip_values (match_id, color, points)`. 色は 7 色だけ, 点数は範囲内だけを制約で許す. 表を足すだけなので, 古いコードのまま当てても壊れない.
- 規則: `src/rules/chip-values.ts` に, 送られた色ごとの点数を確かめる関数を足す.
- DB アクセス: `src/server/db/matches.ts`. マッチ, リーダー, 点数を 1 つの batch で入れる. 点数を読む. マッチを削除するときに点数も消す.
- API: `POST /api/matches` の本文に `chipValues` (`{ "red": 100, "blue": 500 }` の形. ない色は使わない色) を足す. `GET /api/matches/{id}` の応答にも `chipValues` を入れる (`src/server/api/matches.ts`, `match-view.ts`).
- 画面: マッチを作る欄 (`create-section.ts`) に 7 色の見本と点数の欄を出す. 欄の作りは今の設定画面のものを別のファイル (`chip-values-fields.ts`) に移して使う. マッチの画面には, 決めた色と点数を全員に見せる (`match-page.ts`). `api.ts` で応答の形を確かめる.
- テストの観点:
  - 1 色だけ入れたら作れる. 1,000,000,000 なら作れる.
  - 点数が 1 つもない, 0, 1,000,000,001, 小数, 文字なら作るのを拒否する (400).
  - 知らない色の名前があれば拒否する (400). `chipValues` がなければ拒否する (400).
  - 作ったマッチの結果を見ると, 入れた点数が色の順に返る. 入れていない色は返らない.
  - 点数の表に行がないマッチ (この変更より前に作ったもの) では, 空の点数が返る.
  - マッチを削除すると, 点数の行も消える.

#### 2. リーダーが色ごとの点数を変える

- DB アクセス: マッチの点数を 1 つの batch で入れ替える (前の行を消して入れる).
- API: `PUT /api/matches/{id}/chip-values` (本文は `{ "chipValues": {...} }`). リーダーのトークンだけを受け付ける. 確かめる決まりは作るときと同じ規則を使う.
- 画面: マッチの画面の点数の表示の下に, リーダーにだけ「点数を変える」を出す. 押すと 7 色の欄 (今の点数を入れた状態) を出し, 保存したら画面を読み直す. 「変えても, もう保存した持ち点は変わりません」と書く.
- テストの観点:
  - リーダーが変えると, 結果を見たときに新しい点数が返る. 新しい点数から外した色は返らない.
  - 最初のラウンドの前でも, 入力中のラウンドがあっても, 確定したラウンドのあとでも変えられる.
  - 変えても, 保存済みの持ち点と増減は変わらない.
  - リーダー以外のトークンなら拒否する (403). トークンがなければ拒否する (401). マッチがなければ 404.
  - 点数が作るときの決まりを満たさなければ拒否し (400), 前の点数のまま残る.
  - 点数のない古いマッチでも, リーダーが決められる.

#### 3. チップから入力するときに, マッチの点数を使う

- 画面: `chip-input-dialog.ts` は, ブラウザの設定ではなく, マッチの点数を受け取って持ち点を求める. 「色と点数の設定を変える」のボタンと, 設定を先に出す処理を消す. `rounds-section.ts` は「チップから入力」を押したときにマッチを読み直し, 最新の点数で検出画面を開く. 点数がなければ押せなくし, 理由を出す.
- テストの観点: 持ち点を求める規則 (`computeChipPoints`) は変えないので, 今のテストのまま. 画面は人に実機で確かめてもらう (下の「人に頼む確認」).

#### 4. ブラウザに保存する設定を消す

- `src/client/chip-values-store.ts`, `src/client/pages/chip-values-page.ts`, `main.ts` の `/chips`, トップページの「色と点数の設定」のリンク, `rules/chip-values.ts` の保存用の関数 (`readStoredChipValues`, `toStoredChipValues`) とそのテストを消す.
- `/count` (`count-page.ts`) は持ち点を出さず, 今の合計の枚数とスタックごとの確認画像だけを出す.
- `docs/worklog.md` にファイルの追加と削除を記録する.
- テストの観点: 消した関数のテストを消す. 残る規則のテストはすべて通る.

### コミットの分け方

1. `docs: 計画 色ごとの点数をマッチごとにリーダーが決める を残す`
2. `docs: 色ごとの点数をマッチに持たせる仕様にする` (0)
3. `feat: 送られた色ごとの点数を確かめる規則を足す` (1. 規則とテスト)
4. `feat: マッチを作るときに色ごとの点数を保存して返す` (1. migration, DB, API とテスト)
5. `feat: マッチを作る欄で色ごとの点数を入れ, マッチの画面に出す` (1. 画面)
6. `feat: リーダーが色ごとの点数を変える API を足す` (2. DB, API とテスト)
7. `feat: マッチの画面でリーダーが色ごとの点数を変える` (2. 画面)
8. `feat: チップから入力するときにマッチの点数を使う` (3)
9. `refactor: ブラウザに保存する色と点数の設定を消す` (4. worklog も含める)

各コミットの前に `npm run check` を通す.

### 人に頼む確認

- 本番では, merge して push したあとに Actions → migrate で `0004` を当てる必要がある (deploy は当てるまで止まる).
- 実機で次を確かめてもらう.
  - マッチを作るときの点数の欄と, マッチの画面の点数の表示.
  - リーダーが点数を変えられること (ラウンドの途中でも). リーダー以外には「点数を変える」が出ないこと.
  - 「チップから入力」の合計が, 変えたあとの点数で出ること.
  - 点数のない古いマッチでは「チップから入力」が押せず, リーダーが決めると押せるようになること.
  - `/count` が枚数と色だけを出すこと.
