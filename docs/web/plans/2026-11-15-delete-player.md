# リーダーがプレイヤーを削除する

承認日: 2026-11-15

## 人の指示

```
メンバーを削除する機能もつけたいね。できればメンバーが追跡できなくなったら自動削除もしたいがそれはクライアントのトークンだから無理そうじゃないか? メンバーの削除はリーダが行えるようにする。計画せよ
```

```
最初のラウンドを始めたあとは削除もできなくていい。実装せよ
```

## 計画

### 自動削除をしない理由

- トークンを持っているのはその人のブラウザだけで, サーバーはハッシュしか知らない. ブラウザがトークンをなくしても, サーバーには何も届かない.
- 「しばらく開いていない人を消す」は作れるが, 開いていないだけの人とトークンをなくした人を見分けられず, 遊んでいる人を消してしまうおそれがある.
- トークンをなくした人が困るのは, 最初のラウンドの前に同じ名前で参加し直せないとき (前の自分が残っているため). リーダーが前の分を消せば足りる.
  リーダーはラウンドを始める前にメンバーの一覧を確かめるので, そこで気づける.

### 決めること

- できる人: リーダーだけ. 権限はサーバーで毎回確かめる.
- できるとき: 最初のラウンドを始める前だけ. 最初のラウンドを始めた時点で人数 n が固まり, 合計の検査 (Σp = S × n) も確定したラウンドの増減も n で成り立つため.
- リーダー自身は削除できない. マッチにリーダーがいなくなるため.
- 削除のボタンを押したら, 名前と「削除された人は, もう一度参加し直す必要があります」を出して確かめさせる.
- 削除したら, その人の行を DB から消す (最初のラウンドの前なので持ち点はない). 消された人のトークンはそれ以降使えない.
- 消された人がマッチの画面を開いたら, ブラウザに残ったトークンを消し, 「参加する」の欄を出す. トップページの一覧からも外す.
  今は消えたプレイヤーのトークンが残ると参加の欄が出ず, 参加し直せないため.
- 参加の順番を「今の人数 + 1」でなく「今いる人の最大の順番 + 1」で決めるように直す. 途中の人を消すと, 次の人の順番が重なって参加できなくなるため.

### 仕様 (`docs/web/app.md`) に足すこと

「操作と条件」の表に 1 行足す.

| 操作 | できる人 | 条件 | 結果 |
|---|---|---|---|
| プレイヤーを削除する | リーダーだけ | 最初のラウンドがまだ始まっていない. リーダー自身は削除できない | プレイヤーが消え, その人のトークンは使えなくなる |

途中で削除しない理由, 自動削除をしない理由, 消された人の画面がどうなるかも書く. API の表に `DELETE /api/matches/{id}/players/{player_id}` を足す.

### テストの観点

- 規則: 最初のラウンドの前ならリーダー以外を削除できる. 最初のラウンドを始めたあとは拒否する. リーダー自身の削除は拒否する.
- API:
  - リーダーのトークンなら削除でき (204), マッチを読むとその人がいない.
  - リーダーでないプレイヤーのトークンなら拒否する (403). トークンがなければ拒否する (401).
  - 最初のラウンドを始めたあとは拒否する (409). リーダーを消そうとしたら拒否する.
  - いないプレイヤーの id や, 別のマッチのプレイヤーの id なら 404.
  - 消された人のトークンでは, 名前の変更などができない (401).
  - 消したあと, 同じ名前で参加し直せる.
  - 3 人のうち 2 番目を消したあとも, 新しい人が参加できる. 結果の表は参加した順に並ぶ.
- 画面 (人に依頼する):
  - リーダーにだけ, リーダー以外の人の横に「削除」が出る. 最初のラウンドのあとは出ない.
  - 確かめのダイアログで「やめる」を押すと, 何も変わらない.
  - 消された人のブラウザでマッチを開くと, 参加の欄が出て参加し直せる. トップページの一覧からも外れる.

4. `feat: リーダーがプレイヤーを削除する API を足す` (DB, API, テスト)
5. `feat: マッチの画面でリーダーがプレイヤーを削除できるようにする` (画面, app.md)

### この計画に入れないこと

- 最初のラウンドを始めたあとの削除. 途中でトークンをなくした人がいるとラウンドを確定できないが, それは削除では解けず,
  「リーダーが代わりに持ち点を入れる」などの別の機能が要る. 要るなら別の計画にする.
- 自動削除.
