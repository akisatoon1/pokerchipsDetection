```

承認する
```

## 計画

### 決めること

- 出す場所は, トークンを受け取る直前の 2 か所にだけ. トークンを受け取るのはこの 2 つの操作だけで, シークレットで困るのもここだから.
  1. トップページの「マッチを作る」の欄 (見出しの下の説明と, 作るボタンの間). リーダーがトークンをなくすとマッチを進められなくなるので, いちばん大事.
  2. マッチの画面の「参加する」の欄 (見出しと, 名前の欄の間).
- 参加したあとの画面には出さない. 気づいても, もう直せないため.
  `/count` と `/chips` にも出さない. 消えても困るのは色と点数の設定と, 読み込みが重くなることくらいのため.
- Android アプリの中では出さない. WebView にシークレットのモードはないため.
- 文は既存の注意と同じ `warning` の見た目 (橙の文字) にする.
  「シークレット (プライベート) モードでは開かないでください. タブやブラウザを閉じると, このマッチの本人として戻れなくなります.」
- シークレットかどうかの判定はしない. ページからシークレットかを確実に知る方法がブラウザにないため. いつも同じ文を出す.

### 変えるファイル

| ファイル | 変えること |
|---|---|
| `web/src/client/pages/storage-warning.ts` (新規) | 注意書きの要素を作る関数. アプリの中なら何も出さない. 2 か所で同じ文にするため 1 か所に置く |
| `web/src/client/pages/create-section.ts` | マッチを作る欄に注意書きを足す |
| `web/src/client/pages/match-page.ts` | 参加する欄に注意書きを足す |
| `docs/web/app.md` | 「本人の確認」に, 作る欄と参加する欄でシークレットについて注意することを書く |

### テストの観点

- 画面だけの変更で, 規則と API は変えないので, 自動のテストは足さない.
- 画面 (人に依頼する): ブラウザで, トップページの「マッチを作る」と, マッチの画面の「参加する」に注意書きが出る.
  参加したあとのマッチの画面, `/count`, `/chips` には出ない. Android アプリの中では, どちらにも出ない.

### コミットの分け方

1. `docs: 計画 シークレットで開かないよう注意書きを出す を残す`
2. `feat: マッチを作る欄と参加する欄に, シークレットで開かないよう注意書きを出す` (画面と app.md)
