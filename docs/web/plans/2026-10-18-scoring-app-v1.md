## 計画

### 決めたこと

- **技術**:
  - 言語は TypeScript.
  - バックエンドは Cloudflare Workers と Hono.
  - DB は Cloudflare D1.
  - 画面はフレームワークを使わず, TypeScript を Vite でビルドする. Workers の Static Assets で, API と同じドメインから配る.
- **結果を見られる人**: URL を知っていれば誰でも見られる. URL を知っていれば参加もできるので, 見ることだけを制限しても守れるものがないため.
- **値の範囲**:
  - マッチ名は 1〜40 文字.
  - 初期点数 S と持ち点 p の上限は 1,000,000,000. 10 人分の合計でも JavaScript の整数で正確に扱える.
- **ラウンドを始められる最低人数**: 2 人.
- **Node.js**:
  - Node 24 LTS を AI が `~/.local/node` に入れる. sudo は使わない.
  - 公式の tarball を使い, SHASUMS256 で確かめてから展開する.
  - PATH は `~/.bashrc` に 1 行足して通す.
- **依存**:
  - 実行時: `hono`, `zod`.
  - 開発用: `typescript`, `vite`, `vitest`, `@cloudflare/vitest-pool-workers`, `wrangler`, `@cloudflare/workers-types`, `eslint`, `typescript-eslint`, `prettier`.
  - これ以外は足さない.

### 細部の作り方

- **ファイルの置き方**:
  - `web/src/rules/`: 規則. 純粋な関数と, 上限などの定数.
  - `web/src/server/api/`: API.
  - `web/src/server/db/`: DB アクセス. SQL はここにだけ書く.
  - `web/src/client/`: 画面.
  - `web/migrations/`: DB の定義.
  - `web/test/`: テスト.
- **パス**: API は `/api/...` に置き, 画面のパス (`/` と `/m/{matchId}`) と分ける.
- **識別子とトークン**:
  - マッチの id とトークンは `crypto.getRandomValues` で作る 128 ビットの乱数を base64url にする. DB にはトークンの SHA-256 だけを保存する.
  - トークンはブラウザの localStorage にマッチごとに保存し, `Authorization: Bearer` ヘッダで送る. Cookie を使わないので CSRF の心配がない.
- **API の入口**:
  - `Content-Type: application/json` 以外は拒否する. 本文は 4 KB までにする.
  - zod の `.strict()` で, 知らない項目が入っていたら拒否する.
  - CORS のヘッダは出さない. 画面と API が同じドメインなので要らないため.
- **名前**: 前後の空白を除いてから, 文字数 (Unicode の文字単位で数える) を確かめる.
- **DB の制約**:
  - 名前の重なりは UNIQUE 制約で禁じる.
  - 入力中のラウンドが 1 つだけになるよう, 部分 UNIQUE インデックスで守る. 同時に送られても 2 つできない.
- **表示**: 利用者が入れた文字はすべて `textContent` で入れる. `innerHTML` は使わない.
- **エラーの応答**: 何が悪かったかだけを返す. SQL, スタックトレース, トークンは応答にもログにも出さない.
- **テスト**:
  - 規則は Vitest で確かめる.
  - API は `@cloudflare/vitest-pool-workers` を使い, ローカルの D1 で確かめる.
  - 画面は自動テストせず, `wrangler dev` で手で動かして確かめる.
- **コミット前の検査**: `web/` で `npm run check` を流す. 中身は Prettier の確認, ESLint, `tsc --noEmit`, 全テスト, `npm audit`. 通らない状態ではコミットしない.

### 機能と順番

#### 0. 土台

利用者から見た機能ではないが, 最初に要る.

- 変える・作るもの:
  - Node.js の導入 (`~/.bashrc` に PATH を 1 行足す).
  - `web/` の雛形: `package.json` (`engines` で Node 24 を指定), `wrangler.toml`, `tsconfig.json`, `vite.config.ts`, `vitest.config.ts`, `eslint.config.js`, `.prettierrc`, `.gitignore` (`node_modules`, `.wrangler`, `.dev.vars`, `dist` を除く).
  - `docs/web/typescript.md`: TypeScript の書き方, ディレクトリの役割, 検査のコマンド. CLAUDE.md から読み込ませる.
  - `docs/web/app.md`:
    - 「未定のこと」を, 決めた技術に置き換える.
    - 結果を見られる人を「URL を知る人」に直す.
    - マッチ名の決まりと, ラウンドを始めるには 2 人以上要ることを足す.
    - API のパスに `/api` を付ける.
  - `docs/web/scoring.md`: S と p の上限を足す.
  - `docs/worklog.md`: Node の導入, `web/` の構成, 検査のコマンドを記録する.
- テストの観点:
  - 中身のない状態で `npm run check` が通る.
  - `wrangler dev` で空のページが出る.

#### 1. マッチを作る

結果の API と画面の最小限を含む.

- 変える・作るもの:
  - DB: Match と Player の表.
  - 規則: 名前の決まり, マッチ名の決まり, S の範囲, 上限の定数.
  - トークンの発行とハッシュ.
  - API: `POST /api/matches` と, 最小限の `GET /api/matches/{id}` (マッチ名, S, プレイヤーの一覧).
  - 画面: トップの作成フォームと, マッチの画面. 作ったらトークンを保存し, マッチの画面に移る.
- テストの観点:
  - 名前が空, 空白だけ, 21 文字なら拒否する. 1 文字と 20 文字なら受け付ける. 前後の空白は除いて保存する.
  - マッチ名が空, 41 文字なら拒否する. 40 文字なら受け付ける.
  - S が 0, 負の数, 小数, 文字列, 1,000,000,001 なら拒否する. 1 と 1,000,000,000 なら受け付ける.
  - 知らない項目が入っていたら拒否する. 本文が 4 KB を超えたら拒否する. JSON でなければ拒否する.
  - 作った人がリーダーのプレイヤーになり, トークンが返る.
  - DB にはトークンそのものではなく, ハッシュが入っている.
  - マッチの id は作るたびに違い, 128 ビットの乱数の長さがある.
  - 存在しない id を読むと 404 が返り, 応答に内部の情報が出ない.
  - トークンなしでもマッチを読める.

#### 2. 参加する

- 変える・作るもの:
  - API: `POST /api/matches/{id}/players`.
  - 画面: このマッチのトークンを持っていなければ参加フォームを出す. 参加したらトークンを保存する.
- テストの観点:
  - 同じマッチで名前が重なったら拒否する. 別のマッチなら同じ名前で参加できる.
  - 10 人いたら 11 人目を拒否する.
  - 最初のラウンドを始めたあとは参加を拒否する.
  - 参加した人には, 他の人とは違うトークンが返る.
  - 存在しないマッチには参加できない.

#### 3. ラウンドを始める

- 変える・作るもの:
  - DB: Round の表.
  - API: `POST /api/matches/{id}/rounds`. 結果の API にラウンドの一覧を足す.
  - 画面: リーダーにだけ開始ボタンを出す.
- テストの観点:
  - リーダーのトークンなら始められる. リーダー以外のトークン, 別のマッチのトークン, トークンなしでは拒否する.
  - プレイヤーが 1 人なら拒否する. 2 人なら始められる.
  - 入力中のラウンドがあるときは拒否する.
  - ラウンドの番号はマッチごとに 1, 2, … と続く.

#### 4. 持ち点を入れる・直す

確定前の表示を含む.

- 変える・作るもの:
  - DB: Entry の表.
  - 規則: 増減と, 合計の検査.
  - API: `PUT /api/rounds/{id}/entries/{playerId}`. 結果の API に, ラウンドごとの持ち点, 増減, 合計が合っているかを足す.
  - 画面: 自分の持ち点の入力欄と, 入力中のラウンドの一覧 (未入力の表示と警告を含む).
- テストの観点:
  - 本人のトークンなら保存できる. もう一度送れば上書きされる.
  - 他人の playerId に送ったら拒否する. 別のマッチのラウンドに送ったら拒否する.
  - 持ち点が負の数, 小数, 文字列, 1,000,000,001 なら拒否する. 0 と 1,000,000,000 なら受け付ける.
  - 確定したラウンドへの入力は拒否する.
  - 増減は pᵢ − S になる. 入れていない人は「未入力」になる.
  - 全員がそろい, Σp ≠ S×n なら警告の印が付く. そろっていないうちは検査しない.

#### 5. ラウンドを確定する

累計を含む.

- 変える・作るもの:
  - 規則: 累計.
  - API: `POST /api/rounds/{id}/close`. 結果の API に累計と, 確定したラウンドの合計が合っていなかったことの印を足す.
  - 画面:
    - 確定ボタンを押したら, 全員の持ち点と増減の一覧を出して確かめさせる. 合計が合わなければ警告し, 確定するかやめるかを選ばせる.
    - 累計の表を出す.
- テストの観点:
  - リーダーでなければ拒否する. 未入力の人がいたら拒否する.
  - 合計が合っていなくても確定できる. 確定したあとも, 合っていなかったことの印が残る.
  - 確定したあとは, 持ち点の入力も, もう一度の確定も拒否する.
  - 確定したあとは, 次のラウンドを始められる.
  - 累計には確定したラウンドだけが入る. 入力中のラウンドは入らない.
  - `scoring.md` の例 (S=100, 3 人, 2 ラウンド) で, 累計が +30, +50, −80 になる.

#### 6. 名前を変える

- 変える・作るもの:
  - API: `PATCH /api/matches/{id}/players/{playerId}`.
  - 画面: 本人にだけ名前の変更欄を出す.
- テストの観点:
  - 本人なら変えられる. 他人のトークンでは変えられない.
  - 名前の決まりを満たさないとき, 他の人と重なるときは拒否する. 自分の今の名前と同じなら受け付ける.
  - ラウンドを始めたあとでも変えられる. 確定したラウンドも新しい名前で表示される.

### コミットの分け方

- 最初に `docs: 計画 点数計算アプリの最初の版を残す` をコミットする. この計画を残すため.
- 土台は 2 つに分ける.
  1. `chore: Web アプリの雛形と検査を作る`
  2. `docs: Web アプリの技術と決めた値を書く` (`typescript.md`, `app.md`, `scoring.md`, `CLAUDE.md`, `worklog.md`)
- 機能 1〜6 は, それぞれ次の 3 つに分ける.
  1. 規則とそのテスト (`feat:`). 規則のない機能では省く.
  2. DB と API とそのテスト (`feat:`).
  3. 画面 (`feat:`). 進み具合のチェックもこのコミットで付ける.
- 検査が通らないときや計画どおりに進められないときは, 止まって説明する.
- デプロイ, Cloudflare のアカウントの操作, push はしない. 開発はローカル (`wrangler dev` とローカルの D1) だけで行う.
