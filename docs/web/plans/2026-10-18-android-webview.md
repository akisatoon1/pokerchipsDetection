## 計画

### 決めたこと (話し合いで決めたもの)

- Android アプリは, マッチの画面を WebView で表示する. マッチの作成, 参加, 入力, 確定, 結果は Web と同じ画面を使う.
- Compose で作るのは, 検出画面, 色と点数の設定画面, 数えるだけの画面 (今の機能. 実機での確認用に残す) だけにする.
- チップから持ち点への計算は Android で行う. バックエンドは今までどおり持ち点だけを受け取る.
- 色と点数の対応は端末に 1 つ持ち, どのマッチでも同じ対応を使う.
  - 色は core が判定する 7 色 (赤, 青, 黄, 黒, 灰, 紫, 緑) に固定する. 灰は実物では白に見えるので, 色の見本を並べる.
  - 1 色につき 1 以上の整数. 空欄は「使わない色」.
  - 対応がまだないときに「チップから入力」を押したら, 先に設定画面を出す.
- 検出から入力の流れ
  - 「チップから入力」は, アプリの中で, 入力中のラウンドの自分の欄にだけ出す.
  - 撮影かギャラリーで画像を選び, 解析し, 確認画像と色ごとの内訳と合計を出す. スタックが複数あれば合計する.
  - 「この点数を入れる」で入力欄に入れる. 送信は人がボタンを押したときに行う.
  - 枚数を数えられなかったスタック, `unknown` の色, 点数を決めていない色が 1 つでもあるか, 合計が上限を超えるときは止め, 手入力を促す.
- アプリの画面
  - 上のバーに戻る, 更新, メニュー (数えるだけ / 色と点数の設定).
  - アプリを開くと Web のトップページを出す.
  - 更新はボタンと下に引く操作の両方. 戻るボタンで WebView の中で 1 つ前に戻り, トップページならアプリを閉じる.
  - 他のサイトへのリンクは外のブラウザで開く.
  - サーバーにつながらないときは「つながりません」と再試行のボタンを出す.
- Web のトップページに, 参加中のマッチの一覧と, URL を貼って参加する欄を足す (ブラウザとアプリで共通).
- 参加の URL はコピーで送る.
- マッチを削除する操作を足す. 削除できるのはリーダーだけ. プレイヤーが一覧から外す (非表示にする) 機能は作らない.
- 見つからないマッチは一覧から自動で消す.
- bridge で Web からアプリに頼めるのは「チップから入力」と「URL をコピー」だけ. トークンはアプリに渡さない.
- 先にローカルで作る. 本番へのデプロイは今回の計画に入れない.
- この計画に限り `android/` の変更を許す. Kotlin の規約は Web の規則に合わせ, `docs/web/kotlin.md` に書く.

### 決めたこと (計画を作る中で決めたもの)

- **参加中のマッチの一覧は, トップページを開くたびに API で読み直す.**
  前の整理では「名前は参加したときに保存する」としていたが, それでは消されたマッチが分からず, 自動で消せない.
  そのため, 端末に保存するのはトークンと最後に開いた日時だけにし, マッチ名と自分の名前は `GET /api/matches/{id}` で毎回読む.
  - 404 が返ったマッチは一覧から自動で消す.
  - ほかの失敗 (つながらないなど) のときは消さずに「読み込めませんでした」と出す.
- **URL を貼って参加する** ときに受け付けるのは, 自分のサイトの `/m/{id}` だけにする. この判定は規則 (`src/rules/`) の純粋な関数にし, テストする.
- **マッチの削除は完全に消す.** ラウンドの途中でも消せる. 消したあと, リーダーの端末からトークンを消し, トップページに戻す.
- **接続先**: debug では `http://localhost:8787` につなぎ, `adb reverse tcp:8787 tcp:8787` で PC の `wrangler dev` に届ける.
  エミュレータでも実機でも同じ手順で試せるようにするため. 平文の http は debug のビルドで localhost にだけ許す.
  release の接続先は, デプロイするときに決める.
- **アプリの中でのコピーは bridge で行う.** WebView ではブラウザのコピーの機能が確実には動かないため.
- 持ち点の上限 (1,000,000,000) は Kotlin にも定数として置く. 言語が違って共有できないので, `web/src/rules/limits.ts` と同じ値だとコメントに書く. 最後はサーバーが確かめる.

### 承認されたこと

- **触る場所の例外**: この計画に限り, `android/` と `docs/architecture.md` (Android の設計の節) の変更を許す.
- **依存を 3 つ足す** (Android):
  - `androidx.webkit`: bridge を自分のドメインのページだけから呼べるようにするため.
  - `androidx.swiperefreshlayout`: 下に引いて更新するため. Compose の更新の部品は WebView のスクロールと連動しないため.
  - `junit`: Kotlin の純粋な関数の単体テストのため.
- **Android の検査**: Android を変えたコミットの前に, `android/` で `./gradlew assembleDebug testDebugUnitTest lintDebug` を通す.
  lint は AGP に入っているので依存は増えない. Web を変えたときは今までどおり `npm run check` を通す.

テストの観点:

- リーダーのトークンなら削除でき, そのあと `GET` は 404 になる.
- 削除すると, そのマッチのプレイヤー, ラウンド, 持ち点も DB から消える.
- 別のマッチは消えない.
- リーダーでないプレイヤーのトークンなら 403 を返し, 何も消えない.
- トークンがない, または別のマッチのトークンなら 401 を返す.
- ないマッチなら 404 を返す.
- 入力中のラウンドがあっても削除できる.
- 削除したあと, 元のプレイヤーのトークンで持ち点を入れようとしても受け付けない.
- 画面 (手で確かめる): 確認のダイアログにマッチ名と「元に戻せない」が出る. 「やめる」なら何も起きない.
  削除するとトップページに戻り, 消したマッチの URL を開くと「マッチが見つかりません」と出る.

| ファイル | 変えること |
|---|---|

| `.../ui/ChipInputScreen.kt` (新規) | 撮影かギャラリー, 解析, 確認画像, 内訳と合計, 「この点数を入れる」, 設定への移動 |

| `android/app/src/test/` | 下の観点 |

テストの観点:

- 単体テスト
  - 1 つのスタックの持ち点が, 色ごとの枚数 × 点数の和になる.
  - スタックが複数あれば合計する.
  - 内訳は色ごとに枚数と小計を返す.
  - スタックが 1 つも見つからなければ止める.
  - 枚数を数えられなかったスタックがあれば止め, 何番目のスタックかを返す.
  - 色が `unknown` のチップがあれば止め, 何番目のスタックの何枚目かを返す.
  - 点数を決めていない色のチップがあれば止め, その色と場所を返す.
  - 合計が 1,000,000,000 を超えたら止める.
  - 止める理由が複数あれば, すべて返す.
- 手で確かめる
  - ボタンはアプリの中で, 入力中のラウンドの自分の欄にだけ出る. ブラウザでは出ない.
  - 対応をまだ決めていなければ, 先に設定画面が出る.
  - 「この点数を入れる」で欄に持ち点が入り, 送信はされない. 送信のボタンで保存される.
  - 戻るボタンで閉じると, 欄は変わらない.
  - 止まったときは理由が出て, 「この点数を入れる」は押せない.
  - 検出画面から設定を変えて戻ると, 合計が計算し直される.
