# ラウンドを始める前にメンバーを確かめる

承認日: 2026-10-18

## 人の指示

```
機能の修正. 
ラウンドを始めるボタンは押したら始まってしまう. 途中参加をするのでその前に人数が足りているかメンバーがちゃんと参加しているかを知りたい.
ラウンドを始めるまえに参加しているメンバーを表示して, 途中参加ができないことを伝えるフェーズを挟んで.
まずは計画せよ
```

「途中参加をするので」は「途中参加ができないので」の打ち間違いと読み, 途中参加はできないままにする.
決めてほしいこと (2 ラウンド目以降の確認は出さない, 確認したあとの参加はサーバーで拒否する) は, 提案どおりで承認された.

## 計画

### 決めたこと

- **確認のダイアログを挟む**: リーダーが最初のラウンドの「ラウンドを始める」を押したら, すぐには始めない. 先に確認のダイアログを出す.
  - ダイアログを開く直前に, 最新のプレイヤーを API から読み直す.
  - ダイアログには, 参加しているメンバーの一覧と人数, 「始めると, これ以上だれも参加できません」という注意を出す.
  - 「始める」を押したときだけ始まる. 「やめる」なら何も起きない.
- **2 ラウンド目以降**: ダイアログは出さず, 今までどおりすぐ始める. 最初のラウンドのあとはメンバーが変わらないので, 毎回確かめる必要がないため.
- **確認したあとに参加があったとき**: サーバーで拒否する.
  - 画面は, 確認したときの人数を一緒に送る.
  - サーバーは, 今の人数と違えば 409 と「参加者が変わりました. 確かめ直してください」を返し, ラウンドを作らない.
  - ダイアログを見ている間に誰かが参加すると, リーダーが見ていないメンバーでラウンドが始まってしまうのを防ぐため.
- **参加する人への注意**: 共有の URL の欄に「最初のラウンドが始まると, 参加できなくなります」と出す. 参加する側にも締め切りを伝えるため.

### 機能と順番

#### 1. ラウンドを始める前にメンバーを確かめる

変える・作るもの:

| ファイル | 変えること |
|---|---|
| `docs/web/app.md` | 「操作と条件」に, 最初のラウンドの前に確認を挟むこと, 確認した人数を送ることを書く |
| `web/src/rules/rounds.ts` | `checkCanStartRound` の判定に「確認した人数と今の人数が同じか」を足す |
| `web/src/server/api/matches.ts` | `POST /api/matches/{id}/rounds` の本文を `{}` から `{ playerCount: number }` に変える |
| `web/src/client/api.ts` | `startRound` で人数を送る |
| `web/src/client/pages/match-page.ts` | 確認のダイアログと, 共有の欄の注意 |
| `web/test/` | 下の観点のテスト |

テストの観点:

- 規則
  - 確かめた人数と今の人数が同じなら始められる.
  - 確かめた人数と今の人数が違えば拒否する.
- API
  - 今の人数と同じ `playerCount` を送れば始められる.
  - 確かめたあとに 1 人参加して人数が変わったら 409 を返し, ラウンドはできない.
  - `playerCount` がない, 文字列, 負の数, 小数なら 400 を返す.
  - 2 ラウンド目以降も, 同じ人数を送れば始められる.
  - 今までの観点 (リーダーだけ, 2 人以上, 入力中のラウンドは 1 つだけ, 知らない項目は拒否) はそのまま通る.
- 画面 (自動テストはせず, 手で確かめる)
  - 最初のラウンドで押すと, ダイアログにメンバーの一覧, 人数, 途中参加できない注意が出る.
  - 「やめる」でダイアログが閉じ, ラウンドは始まらない.
  - 「始める」でラウンドが始まり, 参加の欄が消える.
  - 2 ラウンド目はダイアログを出さずに始まる.
  - 共有の URL の欄に, 締め切りの注意が出る.
