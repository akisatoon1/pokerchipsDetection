# 点数計算アプリの仕様

みんなで遊んだときの点数を記録し, 計算するアプリの仕様をまとめる.
計算のルールは [scoring.md](scoring.md) にまとめる.

## 全体の構成

```
Android アプリ ──┐
  (WebView.        │  持ち点を送る
   検出で入力を補助) ├──→ バックエンド ── マッチ・プレイヤー・ラウンド・持ち点を保存し, 増減と累計を計算
Web アプリ ───────┘  ←── 結果を表示
  (ブラウザ. 手入力)
```

- マッチの画面 (作る, 参加する, 入力する, 確定する, 結果を見る) は Web にだけ作る.
  Android アプリはその画面を WebView で表示する. 画面を 2 か所で作ると, 確認のダイアログなどの細かい振る舞いがずれるため.
- Android アプリでは, チップを検出して持ち点を入力欄に入れることもできる. 検出は入力を助けるもので, 手で入れてもよい.
- Android を持っていない人は, ブラウザで Web アプリを使う. 自分で持ち点を計算して入力する.
- バックエンドは, 点数の計算と保存を行う. 計算を 1 か所に置き, Android と Web でルールが食い違わないようにする.
- バックエンドが受け取るのは持ち点 (合計点) だけにする. チップの色ごとの点数から持ち点への換算は
  バックエンドに置かない. Android は検出結果から自分で持ち点を計算し, Web の入力欄に入れる.
- Web アプリのコード (フロントエンドとバックエンド) は `web/` に, 文書は `docs/web/` に置く.

## データ

```
Match  : id, 名前, 初期点数 S, leader_player_id
Player : id, match_id, 名前, token
Round  : id, match_id, 番号, 状態 (入力中 / 確定)
Entry  : round_id, player_id, 持ち点 p
```

- 保存するのは持ち点 p だけにする. 増減と累計は保存せず, 読むたびに計算する.
  持ち点を直したときに, 保存した増減と食い違わないようにするため.
- 計算はプレイヤーの id で行い, 名前は表示にだけ使う. 名前を変えても計算には影響しない.

## プレイヤーと名前

- マッチ名は 1〜40 文字にする. 前後の空白は除いてから数える.
- マッチを作った人がリーダーになる. リーダーも作るときに自分の名前を入れる.
- 他の人はマッチの URL から参加し, 名前を入れる. 名前はマッチごとに付ける.
- 1 つのマッチのプレイヤーは 10 人までにする. 公開された URL で大量に参加されないようにするため.
- 途中参加と途中で抜けることは考えない. 最初のラウンドを始めた時点でプレイヤーが固まり,
  人数 n は以後変わらない.
- 名前の決まり:
  - 空は不可で, 1〜20 文字. 前後の空白は除いてから数える.
  - 同じマッチの中で重なる名前は不可. 参加時や変更時にエラーにする. 結果の表で誰が誰か分からなくなるため.
  - 本人ならいつでも変えられる. 確定したラウンドも新しい名前で表示する.

## 本人の確認

ログインは作らない. 参加したときにプレイヤーごとの秘密のトークンを発行し, ブラウザの localStorage に保存する.
トークンはマッチごとに別に保存するので, 1 つのブラウザで複数のマッチに参加できる.
Android アプリでは WebView の中に保存し, アプリのほかの部分には渡さない.

- 持ち点の入力と名前の変更は, 本人のトークンがあるときだけ受け付ける.
- ラウンドの開始と確定は, リーダーのトークンがあるときだけ受け付ける.
- ブラウザのデータを消したり端末を替えたりすると, 本人として戻れなくなる. 仲間内で使うので, これで十分とする.
  同じ端末でも, ブラウザと Android アプリは別のものとして扱われる.

## 操作と条件

| 操作 | できる人 | 条件 | 結果 |
|---|---|---|---|
| マッチを作る | 誰でも | S と名前の決まりを満たす | 作った人がリーダーのプレイヤーになり, トークンを受け取る |
| 参加する | URL を知る人 | 最初のラウンドがまだ始まっていない. 名前の決まりを満たす | プレイヤーになり, トークンを受け取る |
| 名前を変える | 本人だけ | 名前の決まりを満たす | 名前が変わる |
| ラウンドを始める | リーダーだけ | 入力中のラウンドがない. プレイヤーが 2 人以上いる. リーダーが確かめた人数と今の人数が同じ | 新しいラウンドが入力中になる |
| 持ち点を入れる・直す | 本人だけ | そのラウンドが入力中. 持ち点が 0 以上 1,000,000,000 以下の整数 | 自分の Entry を保存・上書きする |
| ラウンドを確定する | リーダーだけ | 全員の持ち点が入っている | ラウンドが確定し, 以後は変更できない |
| 結果を見る | URL を知る人 | なし | 各ラウンドの持ち点・増減と累計を返す |
| マッチを削除する | リーダーだけ | なし. 入力中のラウンドがあってもよい | マッチと, そのプレイヤー・ラウンド・持ち点をすべて消す |

- 入力中のラウンドは常に 1 つだけにする. 確定するまで次のラウンドは始められない.
- プレイヤーの入力は持ち点を保存するだけで, 本人による確定はない. リーダーが確定するまで何度でも直せる.
- リーダーの確定は元に戻せない. 確定したラウンドを取り消す手段も持たせない.
- リーダーが確定ボタンを押したら, 全員の持ち点と増減の一覧を出して確かめさせる.
  合計が合わなければ警告し, そのまま確定するか, やめて直してもらうかを選ばせる.
- マッチを終える操作はない. 確定したラウンドの累計をいつでも見られるので, それで足りる.
- マッチの削除は DB から完全に消し, 元に戻す手段は持たない. 消したことにして残す形にすると,
  戻す操作や残す期間を決める必要が出るため. 仲間内で使うので, 残す理由もない.
  - 削除のボタンを押したら, マッチ名と「全員の結果が消え, 元に戻せない」ことを出して確かめさせる.
  - ボタンはマッチの画面の下のほうに, ほかのボタンと離して置く. 押し間違えないようにするため.
  - 削除したら, リーダーの端末からそのマッチのトークンを消し, トップページに戻す.
  - 消したマッチの URL を開いたら「マッチが見つかりません」と出す.
- 他の人の入力はポーリングしない. リロードしたときに DB の内容を反映する.
- 結果は URL を知っていれば誰でも見られる. URL を知っていれば参加もできるので, 見ることだけを制限しても守れるものがないため.
- ラウンドは 2 人以上いないと始められない. 1 人では点数のやり取りが起きないため.
- リーダーが最初のラウンドの開始ボタンを押したら, すぐには始めず, 参加しているメンバーの一覧と人数を出して確かめさせる.
  始めるとこれ以上だれも参加できないことも伝え, 始めるか, やめて参加を待つかを選ばせる.
  途中参加はできないので, 足りない人がいないかを始める前に確かめられるようにするため.
  2 ラウンド目以降はメンバーが変わらないので, 確かめずにすぐ始める.
- ラウンドを始めるときは, リーダーが確かめた人数を一緒に送る. 今の人数と違えば始めない.
  確かめている間に誰かが参加して, リーダーが見ていないメンバーで始まってしまうのを防ぐため.
- 参加の URL の近くに, 最初のラウンドが始まると参加できなくなることを出す. 参加する側にも締め切りを伝えるため.
- 参加の URL はコピーのボタンで送る. Android アプリの中では, コピーをアプリが行う
  (WebView ではブラウザのコピーの機能が確実には動かないため).

## トップページ

トップページ (`/`) には, 参加中のマッチの一覧, URL を貼って参加する欄, マッチを作る欄を出す.
ブラウザと Android アプリで同じページを使う.

- 参加中のマッチの一覧
  - この端末にトークンを保存したマッチを, マッチ名, 自分の名前, 最後に開いた日時とともに, 最後に開いた順に出す.
    URL をなくしても, 参加したマッチに戻れるようにするため.
  - 端末に保存するのはトークンと最後に開いた日時だけにし, マッチ名と自分の名前は開くたびに API で読む.
    名前を変えたり, リーダーがマッチを削除したりしたことを一覧に反映するため.
  - 見つからない (削除された) マッチは, 一覧から自動で消し, 保存したトークンも消す. 戻る意味がないため.
  - つながらないなど, ほかの理由で読めないマッチは消さずに「読み込めませんでした」と出す.
  - 一覧から外す (非表示にする) 操作は作らない. マッチを消せるのはリーダーの削除だけにする.
- URL を貼って参加する欄
  - 貼った URL のマッチの画面に移る. 参加はその画面で行う.
  - 受け付けるのは, 自分のサイトの `/m/{id}` の URL だけにする. 別のサイトの URL はエラーにする.
    Android アプリには URL の欄がないので, 送られた URL を開く手段として使う.

## Android アプリ

Android アプリは, Web の画面を WebView で表示し, 次の画面だけを自分で持つ.

- 検出画面: チップから持ち点を求め, Web の入力欄に入れる.
- 色と点数の設定画面.
- 数えるだけの画面: マッチに入らずにチップを数える. 検出の結果を実機で確かめるために残す.

### 画面の構成

```
[上のバー]  ← 戻る    更新    ⋮ (数えるだけ / 色と点数の設定)
[WebView]   Web のトップページ または マッチの画面
```

- アプリを開くと Web のトップページを出す.
- 戻る: WebView の中で 1 つ前の画面に戻る. 最初の画面ならアプリを閉じる.
- 更新: 上のバーのボタンと, 画面を下に引く操作の両方で読み直す. 他の人の入力はポーリングしないので,
  ブラウザのリロードの代わりに要る.
- 自分のサイト以外へのリンクは, 外のブラウザで開く. アプリとの連絡口 (bridge) を他のサイトに使わせないため.
- サーバーにつながらないときは, 「つながりません」と再試行のボタンを出す.

### Web とアプリの連絡 (bridge)

- Web からアプリに頼めるのは, 「チップから入力」と「URL をコピー」の 2 つだけにする.
- bridge を呼べるのは, 自分のサイトのページだけにする.
- トークンはアプリに渡さない. アプリが Web に返すのは持ち点の数だけで, 送信は Web が行う.
- Web は, bridge があるかどうかでアプリの中かを判断する.

### チップから入力する

1. 「チップから入力」のボタンは, アプリの中で, 入力中のラウンドの自分の欄にだけ出す.
2. 色と点数の対応がまだなければ, 先に設定画面を出す.
3. 撮影かギャラリーで画像を選び, 解析する.
4. 確認画像 (枚数と色) に加えて, 色ごとの枚数と点数, 合計を出す. スタックが複数あれば合計する.
   ```
   赤  × 5  × 100 =   500
   青  × 3  × 500 = 1,500
   合計             2,000   [この点数を入れる]
   ```
5. 「この点数を入れる」で WebView に戻り, 入力欄に入れる. 送信は人が送信のボタンを押したときに行う.
   検出は間違うことがあるので, 必ず人の目を通すため.

- 次のときは合計を出さずに止め, どのスタックの何枚目かを示して手入力を促す.
  黙って 0 点にすると, 間違いに気づけないため.
  - スタックが 1 つも見つからない.
  - 枚数を数えられなかったスタックがある.
  - 色が判定できなかった (`unknown`) チップがある.
  - 点数を決めていない色のチップがある.
  - 合計が持ち点の上限 (1,000,000,000) を超える.
- 戻るボタンで検出画面を閉じたら, 何も入れない.
- 検出画面から設定を変えたら, 合計を計算し直す.

### 色と点数の設定

- 色と点数の対応は端末に 1 つ持ち, どのマッチでも同じ対応を使う.
  バックエンドに換算を置かないと決めているため. Android の人どうしで対応が違うと合計が合わなくなるが,
  全員の持ち点がそろった時点で合計の検査 ([scoring.md](scoring.md)) の警告で気づける.
- 色は core が判定する 7 色 (赤, 青, 黄, 黒, 灰, 紫, 緑) に固定する. 色を足すのは core の基準色を作り直すときなので,
  アプリの中では足せないようにする. 灰は実物では白に見えるので, 色の見本を並べて, どのチップのことか分かるようにする.
- 1 色につき 1 以上 1,000,000,000 以下の整数を 1 つ持つ. 空欄は「このチップセットでは使わない色」とする.
- 設定画面は, メニューと検出画面から開ける. 数えるだけの画面でも, 対応を決めてあれば合計を出す.

### 接続先

- debug のビルドは `http://localhost:8787` につなぐ. 手元の `wrangler dev` に `adb reverse` で届ける.
  エミュレータでも実機でも同じ手順で試せるようにするため. 平文の http は debug のビルドで localhost にだけ許す.
- release のビルドの接続先は, 本番にデプロイするときに決める.

## API

| 操作 | API |
|---|---|
| マッチを作る | `POST /api/matches` |
| 参加する | `POST /api/matches/{id}/players` |
| 名前を変える | `PATCH /api/matches/{id}/players/{player_id}` |
| ラウンドを始める | `POST /api/matches/{id}/rounds` |
| 持ち点を入れる・直す | `PUT /api/rounds/{id}/entries/{player_id}` |
| ラウンドを確定する | `POST /api/rounds/{id}/close` |
| 結果を見る | `GET /api/matches/{id}` |
| マッチを削除する | `DELETE /api/matches/{id}` |

API は `/api` の下に置き, 画面のパス (`/`, `/m/{matchId}`) と分ける.
トークンは `Authorization: Bearer <token>` ヘッダで送る.

## 技術とホスティング

- 言語は TypeScript. バックエンドは Cloudflare Workers と Hono, DB は Cloudflare D1.
- 画面はフレームワークを使わず, Vite でビルドし, Workers の Static Assets で API と同じドメインから配る.
  同じドメインなので CORS を許す必要がない.
- 無料枠で足り, 仲間内で使うには十分なため.
- 書き方と検査のコマンドは [typescript.md](typescript.md) にまとめる.
