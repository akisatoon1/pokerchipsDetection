# 点数計算アプリの仕様

みんなで遊んだときの点数を記録し, 計算するアプリの仕様をまとめる.
計算のルールは [scoring.md](scoring.md) にまとめる.

## 全体の構成

```
Web アプリ (ブラウザ.        持ち点を送る
  チップの検出で入力を補助) ──────────→ バックエンド ── マッチ・プレイヤー・ラウンド・持ち点を保存し, 増減と累計を計算
                           ←────────── 結果を表示
```

- みんなで使う画面 (マッチを作る, 参加する, 入力する, 確定する, 結果を見る) は, すべて Web に作る.
  iPhone でも Android でも, ブラウザで開いて使う.
- チップを検出して持ち点を入力欄に入れることもできる (下の「チップの検出」). 検出は入力を助けるもので, 手で入れてもよい.
- バックエンドは, 点数の計算と保存を行う. 計算を 1 か所に置き, 画面ごとにルールが食い違わないようにする.
- バックエンドが受け取るのは持ち点 (合計点) だけにする. チップの色ごとの点数から持ち点への換算は
  バックエンドに置かない. 検出した画面が持ち点を計算し, 入力欄に入れる.
  色ごとの点数はマッチに保存するが, バックエンドは保存して返すだけで, 換算には使わない (下の「色ごとの点数」).
- Web アプリのコード (フロントエンドとバックエンド) は `web/` に, 文書は `docs/web/` に置く.

## データ

```
Match  : id, 名前, 初期点数 S, leader_player_id
MatchChipValue : match_id, 色, 点数 (チップ 1 枚の点数)
Player : id, match_id, 名前, token
Round  : id, match_id, 番号, 状態 (入力中 / 確定)
Entry  : round_id, player_id, 持ち点 p
```

- 保存するのは持ち点 p だけにする. 増減と累計は保存せず, 読むたびに計算する.
  持ち点を直したときに, 保存した増減と食い違わないようにするため.
- 計算はプレイヤーの id で行い, 名前は表示にだけ使う. 名前を変えても計算には影響しない.

## プレイヤーと名前

- マッチ名は 1〜40 文字にする. 前後の空白は除いてから数える.
- マッチを作った人がリーダーになる. リーダーも作るときに自分の名前を入れる.
- 他の人はマッチの URL から参加し, 名前を入れる. 名前はマッチごとに付ける.
- 1 つのマッチのプレイヤーは 10 人までにする. 公開された URL で大量に参加されないようにするため.
- 途中参加と途中で抜けることは考えない. 最初のラウンドを始めた時点でプレイヤーが固まり,
  人数 n は以後変わらない.
- 名前の決まり:
  - 空は不可で, 1〜20 文字. 前後の空白は除いてから数える.
  - 同じマッチの中で重なる名前は不可. 参加時や変更時にエラーにする. 結果の表で誰が誰か分からなくなるため.
  - 本人ならいつでも変えられる. 確定したラウンドも新しい名前で表示する.

## 本人の確認

ログインは作らない. 参加したときにプレイヤーごとの秘密のトークンを発行し, ブラウザの localStorage に保存する.
トークンはマッチごとに別に保存するので, 1 つのブラウザで複数のマッチに参加できる.

- 持ち点の入力と名前の変更は, 本人のトークンがあるときだけ受け付ける.
- ラウンドの開始と確定は, リーダーのトークンがあるときだけ受け付ける.
- ブラウザのデータを消したり端末を替えたりすると, 本人として戻れなくなる. 仲間内で使うので, これで十分とする.
  - シークレット (プライベート) モードでは, タブやブラウザを閉じるとトークンが消える.
    そのため, トークンを受け取る直前 (マッチを作る欄と参加する欄) に, シークレットで開かないよう注意を出す.
    ページからシークレットかを確実に知る方法はないので, いつも出す.
  同じ端末でも, ブラウザが違えば別のものとして扱われる.

## 操作と条件

| 操作 | できる人 | 条件 | 結果 |
|---|---|---|---|
| マッチを作る | 誰でも | S と名前の決まりと, 色ごとの点数の決まりを満たす | 作った人がリーダーのプレイヤーになり, トークンを受け取る |
| 参加する | URL を知る人 | 最初のラウンドがまだ始まっていない. 名前の決まりを満たす | プレイヤーになり, トークンを受け取る |
| 名前を変える | 本人だけ | 名前の決まりを満たす | 名前が変わる |
| ラウンドを始める | リーダーだけ | 入力中のラウンドがない. プレイヤーが 2 人以上いる. リーダーが確かめた人数と今の人数が同じ | 新しいラウンドが入力中になる |
| 持ち点を入れる・直す | 本人だけ | そのラウンドが入力中. 持ち点が 0 以上 1,000,000,000 以下の整数 | 自分の Entry を保存・上書きする |
| ラウンドを確定する | リーダーだけ | 全員の持ち点が入っている | ラウンドが確定し, 以後は変更できない |
| 結果を見る | URL を知る人 | なし | 各ラウンドの持ち点・増減と累計を返す |
| 色ごとの点数を変える | リーダーだけ | なし. ラウンドの前でも, 入力中・確定のラウンドがあってもよい. 色ごとの点数の決まりを満たす | マッチの色ごとの点数が置き換わる. 保存済みの持ち点は変わらない |
| マッチを削除する | リーダーだけ | なし. 入力中のラウンドがあってもよい | マッチと, そのプレイヤー・ラウンド・持ち点・色ごとの点数をすべて消す |
| プレイヤーを削除する | リーダーだけ | 最初のラウンドがまだ始まっていない. リーダー自身は削除できない | プレイヤーが消え, その人のトークンは使えなくなる |

- 入力中のラウンドは常に 1 つだけにする. 確定するまで次のラウンドは始められない.
- プレイヤーの入力は持ち点を保存するだけで, 本人による確定はない. リーダーが確定するまで何度でも直せる.
- リーダーの確定は元に戻せない. 確定したラウンドを取り消す手段も持たせない.
- リーダーが確定ボタンを押したら, 全員の持ち点と増減の一覧を出して確かめさせる.
  合計が合わなければ警告し, そのまま確定するか, やめて直してもらうかを選ばせる.
- マッチを終える操作はない. 確定したラウンドの累計をいつでも見られるので, それで足りる.
- マッチの削除は DB から完全に消し, 元に戻す手段は持たない. 消したことにして残す形にすると,
  戻す操作や残す期間を決める必要が出るため. 仲間内で使うので, 残す理由もない.
  - 削除のボタンを押したら, マッチ名と「全員の結果が消え, 元に戻せない」ことを出して確かめさせる.
  - ボタンはマッチの画面の下のほうに, ほかのボタンと離して置く. 押し間違えないようにするため.
  - 削除したら, リーダーの端末からそのマッチのトークンを消し, トップページに戻す.
  - 消したマッチの URL を開いたら「マッチが見つかりません」と出す.
- 他の人の入力はポーリングしない. リロードしたときに DB の内容を反映する.
- 結果は URL を知っていれば誰でも見られる. URL を知っていれば参加もできるので, 見ることだけを制限しても守れるものがないため.
- ラウンドは 2 人以上いないと始められない. 1 人では点数のやり取りが起きないため.
- リーダーが最初のラウンドの開始ボタンを押したら, すぐには始めず, 参加しているメンバーの一覧と人数を出して確かめさせる.
  始めるとこれ以上だれも参加できないことも伝え, 始めるか, やめて参加を待つかを選ばせる.
  途中参加はできないので, 足りない人がいないかを始める前に確かめられるようにするため.
  2 ラウンド目以降はメンバーが変わらないので, 確かめずにすぐ始める.
- ラウンドを始めるときは, リーダーが確かめた人数を一緒に送る. 今の人数と違えば始めない.
  確かめている間に誰かが参加して, リーダーが見ていないメンバーで始まってしまうのを防ぐため.
- 参加の URL の近くに, 最初のラウンドが始まると参加できなくなることを出す. 参加する側にも締め切りを伝えるため.
- プレイヤーの削除は, 最初のラウンドを始める前だけにする. 人数 n はそこで固まり,
  合計の検査 (Σp = S × n) と確定したラウンドの増減は n で成り立つため.
  - トークンをなくした人は, 同じ名前で参加し直せない (前の自分が残っているため). リーダーが前の分を削除すれば参加し直せる.
    リーダーは最初のラウンドを始める前にメンバーの一覧を確かめるので, そこで気づける.
  - トークンをなくした人を自動で削除することはしない. トークンはその人のブラウザにしかなく, なくしてもサーバーには分からない.
    しばらく開いていない人を消す形にすると, 開いていないだけの人まで消してしまうため.
  - 削除のボタンは, プレイヤーの一覧のリーダー以外の人の横に, リーダーにだけ出す. 押したら, 名前と
    「削除された人は, もう一度参加し直す必要があります」を出して確かめさせる.
  - 削除された人がマッチの画面を開くと, ブラウザに残ったトークンを消し, 参加の欄を出す. トップページの一覧からも外す.
- 参加の URL はコピーのボタンで送る. ブラウザのコピーの機能は https (か localhost) で開いたページでしか使えないので,
  手元の LAN で開いたときはコピーできない. そのときは欄の URL を選んでコピーしてもらう.

## トップページ

トップページ (`/`) には, 参加中のマッチの一覧, URL を貼って参加する欄, マッチを作る欄を出す.

- 参加中のマッチの一覧
  - この端末にトークンを保存したマッチを, マッチ名, 自分の名前, 最後に開いた日時とともに, 最後に開いた順に出す.
    URL をなくしても, 参加したマッチに戻れるようにするため.
  - 端末に保存するのはトークンと最後に開いた日時だけにし, マッチ名と自分の名前は開くたびに API で読む.
    名前を変えたり, リーダーがマッチを削除したりしたことを一覧に反映するため.
  - 見つからない (削除された) マッチは, 一覧から自動で消し, 保存したトークンも消す. 戻る意味がないため.
  - つながらないなど, ほかの理由で読めないマッチは消さずに「読み込めませんでした」と出す.
  - 一覧から外す (非表示にする) 操作は作らない. マッチを消せるのはリーダーの削除だけにする.
- URL を貼って参加する欄
  - 貼った URL のマッチの画面に移る. 参加はその画面で行う.
  - 受け付けるのは, 自分のサイトの `/m/{id}` の URL だけにする. 別のサイトの URL はエラーにする.
    アドレス欄を使わずに, 送られたマッチを開けるようにするため.
- 数えるだけの画面 (`/count`) へのリンク.

マッチの画面の一番上 (マッチ名の上) には, トップページへのリンクを置く. 画面には固定しない. 参加中のマッチの一覧や, ほかのマッチに戻れるようにするため.

## チップの検出

チップの山の写真から枚数と色を求め, マッチの色ごとの点数から持ち点を出す.

- Web の画面が検出する. core (チップを数える C++ のロジック) を WebAssembly (WASM) にしたものを画面で動かす.
  iPhone でも Android でも, アプリを入れずにブラウザで検出できるようにするため. core のコードを写さないので, Linux や Android アプリと同じ結果になる.
- 写真はサーバーに送らない. 検出は端末の中で済み, サーバーには持ち点だけが届く.
- 検出器 (WASM とモデル, 約 15MB) は, 初めて解析するときに読み込み, ページを開いている間は使い回す.

| 画面 | 場所 |
|---|---|
| 数えるだけの画面 | `/count` |
| 検出画面 (チップから入力) | マッチの画面に重ねて出す |

### 写真を何枚も使う

チップが 1 枚の写真に収まらないとき (スタックが多い, 横に広い) は, 分けて撮った写真を足し, すべての写真のチップを合わせて数える.
数えるだけの画面と検出画面のどちらでもできる.

- 「撮影する」は押すたびに 1 枚撮って足す. カメラは 1 回に 1 枚しか撮れないため.
  「写真を選ぶ」は写真の一覧から何枚でも選べ, 選んだ写真を 1 枚ずつ順に解析して足す.
  1 枚目を足したあとは, ボタンを「撮影して足す」「写真を選んで足す」にする.
- 写真には足した順に「写真 1」「写真 2」…と番号を付け, 写真ごとに全体画像と確認画像を出す. 写真ごとの表示は開閉でき,
  見出しにスタックの数と枚数を出す. 閉じても何枚と数えたかが分かるようにするため.
- 写真ごとに「この写真を外す」を置き, 撮り直したい写真だけを外せる. 外したら番号を振り直す.
- 同じチップを 2 枚の写真に写すと 2 回数える. 写真から同じチップを見分けることはしないので, 写さないよう案内に書く.
- 写真は 10 枚までにする. 写真ごとに画像を持つので, 端末のメモリを使いすぎないため.
  画像は写真ごとの表示を描いたらすぐ手放す.
- 読めない写真は足さずに理由を出し, 残りの写真は解析を続ける.

### 数えるだけの画面

- マッチに入らずにチップを数える. 撮影するか写真を選び, 解析する. 写真は何枚も足せる (上の「写真を何枚も使う」).
- 元の写真に枠と枚数を重ねた全体画像と, スタックごとの確認画像を出す.
  確認画像は, スタックの枠を広げて切り出し, チップの合わせ目に線を引き, チップごとの色を並べたもの.
  枚数と色が正しいかを一目で確かめられるようにするため. 枠を広げるのは, 枠そのもののずれにも気づけるようにするため.
- 写真が 2 枚以上あれば, すべての写真の合計の枚数を出す.
- 持ち点は出さない. 色ごとの点数はマッチが持つので, マッチに入らない画面には点数がないため.
- 検出の結果を実機で確かめるためにも使う.
- 解析に使った画像を保存する機能は, ブラウザには作らない. 元の写真が端末にそのまま残るため.

### チップから入力する

1. 「チップから入力」のボタンは, 入力中のラウンドの自分の欄にだけ出す.
2. ボタンを押したらマッチを読み直し, 最新の色ごとの点数で検出画面を開く.
   リーダーが点数を変えても他の人の画面はポーリングしないので, 開いたままの画面が古い点数で換算しないようにするため.
   マッチに色ごとの点数がなければ (この仕様より前に作ったマッチ), 検出画面を開かず「リーダーが点数を決めると使えます」と出す.
3. 撮影するか写真を選び, 解析する. 写真は何枚も足せる (上の「写真を何枚も使う」).
4. 確認画像 (枚数と色) に加えて, 色ごとの枚数と点数, 合計を出す. すべての写真のすべてのスタックを合計する.
   合計は写真の一覧の上に出し, 写真を足す・外すたびに出し直す.
   ```
   赤  × 5  × 100 =   500
   青  × 3  × 500 = 1,500
   合計             2,000   [この点数を入れる]
   ```
5. 「この点数を入れる」で検出画面を閉じ, 入力欄に入れる. 送信は人が送信のボタンを押したときに行う.
   検出は間違うことがあるので, 必ず人の目を通すため.

- 次のときは合計を出さずに止め, どの写真のどのスタックの何枚目かを示して, その写真を外して撮り直すか, 手入力を促す.
  黙って 0 点にすると, 間違いに気づけないため.
  - スタックが 1 つも見つからない写真がある.
  - 枚数を数えられなかったスタックがある.
  - 色が判定できなかった (`unknown`) チップがある.
  - 点数を決めていない色 (マッチで使わない色) のチップがある.
  - 合計が持ち点の上限 (1,000,000,000) を超える.
- 検出画面を閉じるボタンで閉じたら, 何も入れない.
- 検出画面を閉じたあとも, 入力中の欄とマッチの画面の位置を保つ.
- 検出画面からは色ごとの点数を変えられない. 変えるのはリーダーがマッチの画面で行う.

### 色ごとの点数

- 色ごとの点数 (チップ 1 枚の点数) はマッチごとに持ち, リーダーがマッチを作るときに決める.
  マッチの全員が同じ点数で換算する. 人ごとに点数が違うと, 同じチップから違う持ち点が出て合計が合わなくなるため.
  - 保存はバックエンドで行うが, 持ち点への換算は画面で行う. バックエンドが受け取るのは今までどおり持ち点だけ.
- リーダーは, いつでも色ごとの点数を変えられる. 最初のラウンドの前でも, 入力中のラウンドがあっても, 確定したラウンドのあとでもよい.
  - 変えても, 保存済みの持ち点は変わらない. 持ち点だけを保存し, 点数は換算に使うだけのため. 変える欄にもそう書く.
  - 変える欄は, マッチの画面の色ごとの点数の表示の下に, リーダーにだけ出す.
- マッチの画面には, 決めた色ごとの点数を全員に見せる. 換算に使う点数を全員が確かめられるようにするため.
- 色は core が判定する 7 色 (赤, 青, 黄, 黒, 灰, 紫, 緑) に固定する. 色を足すのは core の基準色を作り直すときなので,
  画面の中では足せないようにする. 灰は実物では白に見えるので, 色の見本を並べて, どのチップのことか分かるようにする.
- 決まり:
  - 1 色につき 1 以上 1,000,000,000 以下の整数を 1 つ持つ. 空欄は「このチップセットでは使わない色」とする.
  - 少なくとも 1 色は決める. 1 色もなければチップから入力できないため.
- この仕様より前に作ったマッチには色ごとの点数がない. リーダーが変える欄から決めれば, チップから入力できるようになる.

## Android アプリとの関係

点数計算は Web だけで行う. Android アプリ (`android/`) は点数計算には使わず, core のチップの検出を実機で確かめるためだけのアプリにした
([architecture.md](../architecture.md) の 8). アプリは Web を開かず, Web もアプリとは連絡しない.

## API

| 操作 | API |
|---|---|
| マッチを作る | `POST /api/matches` |
| 参加する | `POST /api/matches/{id}/players` |
| 名前を変える | `PATCH /api/matches/{id}/players/{player_id}` |
| ラウンドを始める | `POST /api/matches/{id}/rounds` |
| 持ち点を入れる・直す | `PUT /api/rounds/{id}/entries/{player_id}` |
| ラウンドを確定する | `POST /api/rounds/{id}/close` |
| 結果を見る | `GET /api/matches/{id}` |
| 色ごとの点数を変える | `PUT /api/matches/{id}/chip-values` |
| マッチを削除する | `DELETE /api/matches/{id}` |
| プレイヤーを削除する | `DELETE /api/matches/{id}/players/{player_id}` |

API は `/api` の下に置き, 画面のパス (`/`, `/m/{matchId}`, `/count`) と分ける.
トークンは `Authorization: Bearer <token>` ヘッダで送る.
色ごとの点数は, 色の名前 (core の `chipColorName`) から点数への対応 (`{ "red": 100, "blue": 500 }`) で送り, 返す. ない色は使わない色とする.

## 技術とホスティング

- 言語は TypeScript. バックエンドは Cloudflare Workers と Hono, DB は Cloudflare D1.
- 画面はフレームワークを使わず, Vite でビルドし, Workers の Static Assets で API と同じドメインから配る.
  同じドメインなので CORS を許す必要がない.
- 無料枠で足り, 仲間内で使うには十分なため.
- チップの検出は, core を Emscripten で WASM にしたものを画面から呼ぶ. WASM とモデルも Static Assets で配り,
  誰でも取れる URL に置く. 作り方は [architecture.md](../architecture.md) の「10. Web でも core を WASM にして動かす」にある.
- 書き方と検査のコマンドは [development/web/typescript.md](../development/web/typescript.md) にまとめる.
